直接下载的磁盘映像首次打开仍会被 macOS 拦截，这一点只有 Apple Developer ID 能解决，已决定不买。通过 Homebrew 安装时，cask 在安装后去掉隔离标记，不再拦截（2026-11-27 起）。

### 已决定不做

音量调节；把窗口移到相邻桌面；长按空格与按键序列激活；瞬时切换桌面；Caps Lock 作为 Hyperkey；搜索与标签合并成一个模式。

### 做了但验证不充分

- 图标识别只在一张测试图上试过（14 个图标识别出 10 个），没有在真实应用上验证。
- 键盘拖拽验证过同一窗口内拖文件，跨窗口拖拽和拖分隔条没有试。
- 多显示器下的桌面切换、旧系统（macOS 15 及更早）上的调度中心标签没有实测。
- 兼容模式的效果没有观察到：测试用的 Mac 上没有 Firefox，而且所有应用本来就处于该状态。
- 导出/导入、复制诊断信息、隐藏菜单栏图标、按应用设置的界面只有单元测试，没有在运行中的应用里点过。


## 1. 结论

Keyfari 在“给界面元素打标签并点击”这件核心的事上已经不输 Vimac，多数地方也追上了 Homerow。接下来最该做的不是再加模式，而是三件让人愿意长期用下去的事：

1. **装上之后不再反复要权限**（稳定签名 + 更新检查）。
2. **第一次打开就知道怎么用**（首次引导）。
3. **搜索模式跟上标签模式**（也覆盖所有可见窗口）。

之后再做图标按钮识别、键盘拖拽、Dock 标签这类扩大覆盖面的功能。

## 2. 产品定位

- **是什么**：macOS 上的键盘导航工具。按一个快捷键，屏幕上能点的东西都出现短标签，敲标签即点击。
- **给谁用**：手不想离开键盘的人，主要是开发者和重度键盘用户；其次是因手腕不适想少用鼠标的人。
- **原则**（来自现有代码和文档，后续设计都遵守）：
  - 免费开源，GPL-3.0。
  - 不联网、无遥测，数据只留在本机。
  - 只用公开 API。
  - 目前没有第三方依赖，新增依赖要先讨论。

## 4. 与 Vimac、Homerow 的功能差距

来源说明：
- **Homerow 设置项**来自你提供的 7 张设置界面截图，以及它的官网更新日志（最新一条是 3.0.0，2026-11-16）。
- **Vimac** 来自它的 GitHub 仓库（README、`docs/manual.md`、源码），最后一次提交在 2022 年底，README 写明“Vimac is now Homerow”。
- 标“未核实”的条目，只在截图或更新日志里见到名字，没有找到说明它具体做什么的资料。
- “Keyfari 没有”这一列，我都在代码里搜过对应的接口确认不存在。

### 4.1 Keyfari 缺、对方有

| 功能 | Vimac | Homerow | 说明 |
|---|---|---|---|
| 自动更新 | 有（Sparkle） | 有（Sparkle，可开关） | Keyfari 只能手动下载或用 Homebrew |
| 首次引导 | 无 | 有（3.0 新增） | Keyfari 首次启动只弹系统权限框 |
| 自定义滚动键 | 有 | 有（Scroll keys） | Keyfari 的 `H J K L D U G` 写死在代码里 |
| 滚动模式方向键 | 无 | 有（Arrow keys：Select / Scroll） | Keyfari 的方向键只用来切换滚动区域 |
| 滚动模式自动退出 | 无 | 有（Auto deactivation，未核实细节） | |
| 隐藏滚动区域编号 | 无 | 有（Show scroll area numbers） | Keyfari 始终显示 |
| 浏览器标签策略 | 无 | 有（Fast / Exhaustive，未核实细节） | Keyfari 只有一种策略 |
| Firefox 等应用的兼容开关 | 有（Emulate VoiceOver） | 未核实 | Keyfari 只处理了 Electron，没有设置 `AXEnhancedUserInterface` |
| 标签模式中隐藏鼠标指针 | 有 | 未核实 | Keyfari 不隐藏 |
| Caps Lock 作为 Hyperkey | 无（建议用 Karabiner） | 有 | |
| 仅修饰键的快捷键 | 无 | 有（1.1.0） | Keyfari 的快捷键必须带一个普通键 |
| 统计的活动热力图 | 无 | 有（截图里的日历格子） | Keyfari 只有四个数字 |
| 设置窗口的浅色/深色切换 | 无 | 有（Auto / Light / Dark） | Keyfari 跟随系统 |
| 隐藏菜单栏图标 | 无 | 有（Show menubar icon） | |
| 音量调节 | 无 | 有 | Keyfari 只有开关 |
| 无文字按钮的识别 | 无 | 有（Vision Detection，按需下载模型） | Keyfari 只识别文字，图标按钮没有标签 |
| 瞬时切换桌面（跳过动画） | 无 | 有（Pro） | Keyfari 走系统快捷键，带动画 |
| 搜索与标签合一 | 无 | 有（未核实 3.0 是否仍如此） | Homerow 的说明里是同一个模式；Keyfari 是两个模式 |

### 4.2 已决定不做，本文忽略

- 长按空格激活（已移除）。
- 按键序列激活（已移除）。
- 把窗口移到相邻桌面（暂缓，见 issue #18）。

### 4.3 Keyfari 有、对方没有或未见

供定位参考，不展开：所有显示器的所有可见窗口同时打标签（Homerow 官网写的是“标签出现在活动屏幕上”）；中文拼音搜索；完全离线、无遥测（Vimac 有无法关闭的匿名统计，Homerow 有 Sentry 分析）；免费（Homerow 一次性 25 美元）。

## 5. 从用户角度：我想要什么

下面按“我作为每天用它的人会在什么时候烦”来排，不是按实现难度。

### P0-1 装一次，权限给一次

**现在的痛点**：每次更新后，macOS 都要求重新授予辅助功能和屏幕录制权限，因为应用是临时签名，每次构建签名都变。这是目前最劝退的一点，比缺任何功能都严重。

**决定**：不购买 Apple 开发者账号，所以不做 Developer ID 签名和公证。

**剩下能做的**
- 用一个固定的自签名证书给发布版签名。权限可以跨版本保留，但首次打开仍会被 macOS 拦截，这一点改变不了。
- 构建脚本已经支持指定签名身份（`KEYFARI_SIGN_IDENTITY`）。要用在正式发布上，需要你在钥匙串里创建一个代码签名证书，并把它配置成发布流程的密钥。证书和私钥只能由你本人生成和保管，这一步无法代劳。
- 在此之前，README 和首次引导里要把“更新后需要重新授权”说清楚，并给出最短的操作路径。

**验收**：使用固定证书后，从一个版本升到下一个版本，不重新授权即可使用两种权限。

### P0-2 知道有新版本（已实现，待合并）

**决定**：接受这一个网络请求。

**行为**
- 每天检查一次：向 GitHub 询问本项目的最新发布，不带任何标识，不发送任何关于用户或电脑的信息。
- 有新版本时弹出提示，请用户下载。四个选择：下载（在浏览器打开发布页）、以后再说、跳过这个版本、不再检查更新。
- Keyfari 自己不下载、不替换程序。
- 设置的“通用”里有开关、“立即检查”按钮，以及取消跳过的入口；菜单栏菜单里有“检查更新…”。
- 不引入 Sparkle，保持没有第三方依赖。

**验收**：开启时，新版本发布后 24 小时内出现提示；跳过的版本不再提示，但更新的版本照常提示；关闭后没有任何网络请求。

### P0-3 第一次打开的引导

**现在的痛点**：装好后只看到系统的权限弹窗和菜单栏多了个图标，不知道快捷键是什么、该按什么。

**方案**：首次启动显示一个三步窗口。
1. 授予辅助功能权限，实时显示“已授权”。
2. 试一次：窗口里放几个按钮，提示按 `⇧⌘Space` 再敲标签，点中即过关。
3. 可选项：屏幕录制权限（文字识别）、登录时启动、更新检查。

以后可以从设置里重新打开。

**验收**：全新安装的用户不看 README 也能在一分钟内完成第一次标签点击。

### P0-4 搜索模式也覆盖所有可见窗口

**现在的痛点**：标签模式已经能点其他显示器上的窗口，搜索模式还只搜当前窗口，两个模式行为不一致。

**方案**：搜索模式复用同一套“可见窗口”查询；匹配结果按“当前窗口优先，其次指针所在屏幕，再其次其他屏幕”排序；点击后台窗口同样先把它提到前面。

**验收**：在另一块屏幕的窗口里有“保存”按钮时，搜索 `bc` 能找到并点中它。

### P1-1 没有文字的按钮也能点

**现在的痛点**：很多应用的工具栏只有图标，辅助功能树里又没有，文字识别也识别不到，只能回去用鼠标。README 里把它列为“尚未支持”。

**决定**：不使用需要下载的模型，只用 Apple 系统自带的识别能力。

**方案**
- 在现有文字识别的同一张截图上，再用系统 Vision 框架找“像按钮的区域”：矩形和轮廓检测找出规则的小块，显著性分析排除大面积背景。
- 按尺寸（接近图标大小）、排列（成行或成列、间距均匀）和位置（靠近窗口边缘的工具栏区域）筛选，先覆盖工具栏这类规则排列的图标。
- 已经有标签的区域不重复添加，和现在处理文字区域的方式一致。
- 沿用现有开关（关闭 / 需要时 / 始终），不新增设置；全程在本机完成，没有网络请求。
- 预期的局限：没有模型，分不清“图标”和“装饰图形”，会有误标和漏标；无规律散布的图标识别率会低。

**验收**：在一个只暴露窗口本身、工具栏全是图标的应用里，多数工具栏图标有标签，且误标不至于盖住正常标签。具体比例要先做原型才能定。

### P1-2 键盘拖拽

**现在的痛点**：把文件拖进窗口、调整分栏宽度、拖动滑块，这些只能用鼠标。

**方案**：标签模式里增加“拖拽”动作。敲第一个标签时按住某个修饰键表示“从这里按下”，标签不消失，再敲第二个标签表示“拖到这里松开”。中间可以按 `Esc` 取消并松开。

**验收**：能把访达里的文件拖进另一个窗口，能拖动分栏的分隔条。

### P1-3 Dock 和更多系统界面的标签

**现在的痛点**：标签覆盖了菜单栏和通知，但 Dock 里的图标点不了。

**方案**：把 Dock 的图标作为一类来源加入标签模式，可在设置里关掉。Dock 自动隐藏时不打标签。

**验收**：Dock 可见时，每个图标都有标签，敲标签等同点击。

### P1-4 滚动模式更顺手

对应 4.1 里滚动相关的几项，合成一组做：

- 自定义滚动键（照顾 Dvorak 等布局的用户）。
- 方向键也能滚动，可选。
- 一段时间不操作后自动退出，可选，默认关。

**验收**：把滚动键改成 `D H T N` 后，滚动、半页、顶部/底部都按新键工作。

### P1-5 重复上一次点击

**现在的痛点**：翻页、点“下一步”这类操作要反复“按快捷键、敲同一个标签”。固定标签解决了“标签不变”，但还是两步。

**方案**：一个可选的全局快捷键，直接再点一次上次点过的那个元素（按固定标签的识别方式重新找到它，找不到就提示）。

**验收**：在分页列表里点过一次“下一页”后，按这个快捷键能连续翻页。

### P2 小改进

| 功能 | 说明 |
|---|---|
| 统计热力图 | 把每天的点击数画成日历格子，一眼看出哪几天用得多 |
| 导出/导入设置 | 换电脑时带走设置和自定义标签；纯本地文件 |
| 复制诊断信息 | 设置里一个按钮，复制系统版本、应用版本、权限状态，方便报 bug |
| 隐藏菜单栏图标 | 隐藏后用快捷键或再次打开应用进入设置 |
| 标签模式时隐藏指针 | 避免指针挡住标签 |
| Firefox 等应用的兼容开关 | 设置 `AXEnhancedUserInterface`，默认关，因为它会影响窗口管理工具 |
| 每个应用单独的设置 | 例如只在某个应用里开“始终识别文字”或关“所有窗口” |
| 音量调节 | 现在只有开关 |

### 暂不建议做

- **瞬时切换桌面**：要跳过系统动画，公开接口做不到。
- **Caps Lock 作为 Hyperkey**：要常驻改写键盘事件，和“不用时什么都不做”的定位冲突；已有 Karabiner 这类成熟工具。
- **搜索与标签合并成一个模式**：Keyfari 的两个模式各自清楚，合并会改变所有老用户的习惯，收益不明确。

## 7. 怎么判断做对了

Keyfari 没有遥测，所以不能看使用数据，只能看这些：

- 0.3 之后，“更新后又要重新授权”类的 issue 不再出现。
- 新用户的 issue 里，“装好不知道怎么用”类的问题减少。
- 本机统计里“节省的时间”和连续天数，用户自己看得到增长（这也是统计功能存在的理由）。
- GitHub 的 star、Homebrew 安装量作为粗略的外部信号。

## 8. 已做的决定

| 问题 | 决定 | 影响 |
|---|---|---|
